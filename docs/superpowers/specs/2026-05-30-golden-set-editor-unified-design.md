# Golden Set Editor — Unified Design

**Date:** 2026-05-30
**Status:** Approved, pending implementation

## Background

The existing Golden Set editor has two completely separate UIs driven by a single boolean (`hasAutoGenerated`). If any query in the set was auto-generated or imported, the entire page switches to a review-card layout that strips out source management, reference answer editing, and the ability to add manual queries. If all queries are manual, a master-detail layout is shown with full editing. This split creates capability gaps that cannot be resolved without deleting and re-creating queries.

The new design replaces both modes with a single unified editor. Auto-generation becomes a convenience action that seeds the list — nothing more. All queries, regardless of origin, are treated identically after creation.

## Goals

- One editor layout for all query origins (manual, auto-generated, imported)
- Auto-generation is one-shot and additive — it seeds the list then steps aside
- Every query exposes all fields: text, reference answer, expected sources
- No review status workflow (accept/reject/pending) — dropped entirely
- Source method (Manual / Auto / Imported) is informational only, surfaced for navigation filtering, never gates editor behaviour

## Out of Scope

- Drag-to-reorder queries
- Streaming auto-generation results (queries appear as batch when generation completes)
- Auto-save with conflict resolution (last write wins, single user assumed)

## Layout

The page has three zones.

### Page Header

Full width, above both panels. Contains: golden set name (left), status badge Draft/Completed (left), and three action buttons on the right — **Import**, **Auto-Generate**, **Mark as Completed**. The header is fixed and never changes based on selection state.

### Left Panel (≈300px, fixed width)

A query navigation list. Contents top to bottom:

1. **Panel header row** — "Queries (N)" label and a "+" button to create a new query.
2. **Search input** — filters the list client-side in real time, case-insensitive match against full query text.
3. **Source method filter chips** — All / Manual / Auto / Imported. Filters compound with search. Purely a navigation aid; has no effect on editor behaviour.
4. **Query list** — scrollable, variable-height rows. Each row shows the full query text (no truncation) and a small metadata line beneath it: source count and a muted origin tag. Selected row has a highlighted background and a left accent bar.

Query ordering is oldest-first (creation date ascending). Newly created queries appear at the bottom. Ordering is stable; the list does not reorder as the user works.

### Right Panel (fills remaining width)

The unified query editor. Shows a centred placeholder ("Select a query or create a new one.") when nothing is selected. When a query is selected, the editor loads immediately with all fields ready to edit — no edit-mode toggle.

## Unified Query Editor (Right Panel)

The same component renders for every query regardless of how it was created.

### Fields

**Query text** — auto-resizing textarea at the top of the panel. No label; it is visually the headline. Saves on blur and on Ctrl+Enter. A muted "Saved ✓" indicator appears briefly after each save.

**Reference Answer** — separated from query text by a divider. Label: "Reference Answer". Description beneath label: "Optional ideal answer used during judge evaluation." Auto-resizing textarea. Saves on blur and Ctrl+Enter. Placeholder: "Add an expected answer… (optional)". Always visible and editable for all queries.

**Expected Sources** — separated by a divider. Label: "Expected Sources" with an "Add Source" button in the same header row. Shows the current sources list — each entry displays document name and page number badges with a delete icon. Empty state: "No sources yet — add a document source to define expected retrieval results." Clicking "Add Source" opens the existing `AddSourceDialog` unchanged.

**Metadata footer** — at the very bottom, visually de-emphasised in muted text. Shows: origin (Manual / Auto-generated / Imported) and creation date. For auto-generated queries only, also shows question type and reasoning. Reasoning is shown in a lightly shaded read-only box. These fields are never editable.

### Delete

A trash icon button in the top-right corner of the right panel. Clicking shows an inline confirmation line beneath the icon: "Delete this query? Yes / Cancel". No modal. Confirming deletes via API and auto-selects the adjacent query in the list.

### Save Behaviour

All saves are per-field, triggered by blur or Ctrl+Enter. There is no form-level Save button. If the user clicks a different query in the left panel while a field is focused and dirty, the field saves before the new query loads. This prevents accidental loss without requiring explicit save actions.

## Left Panel Interactions

### Creating a New Query

Clicking "+" calls the API to create a blank query with `sourceMethod: 'manual'`. The new entry is appended to the bottom of the list, auto-selected, and the right panel loads with focus in the query text textarea. The list entry shows a muted placeholder ("New query…") until text is saved.

### Search

Client-side, real-time filter on query text. Compounds with the source method chip. Shows "No matches" when nothing passes both filters. Clearing search restores the full list with the current selection scrolled into view.

### Source Method Filter

Four chips: All (default), Manual, Auto, Imported. Active chip narrows the list. Combined with search. Does not affect the editor.

### Keyboard Navigation

Up/Down arrows move selection when focus is in the list. Enter moves focus to the query text textarea in the right panel.

## Auto-Generation Dialog

Opened by the "Auto-Generate" button in the page header. A standard dialog (not full-screen, not a separate page). Two sequential states with no back navigation once generation starts.

### Configuration State

**Generation settings group:**
- Document multi-select — only documents with status `ready` are shown
- Queries per document — number input
- Question types — checkboxes: Factual, Comparison, Summarization (at least one required)

**LLM Configuration group:**
Full `PromptConfigEditor` component. The `systemPrompt` textarea is pre-populated with the default generation system prompt. The default prompt is extracted from the backend's `_build_generation_prompt` method into a named Python constant (`DEFAULT_GENERATION_SYSTEM_PROMPT`) and duplicated as a TypeScript constant in the frontend — no API call is needed to fetch it. The placeholder reads "Using default generation prompt…" when empty. A "Reset to default" text link sits below the textarea and restores the TypeScript constant into the field. If the user submits with an empty system prompt field, the backend falls back to `DEFAULT_GENERATION_SYSTEM_PROMPT`.

`structuredOutput` and `tools` capabilities are disabled for this dialog.

**Footer:** "Generate" button (disabled until ≥1 document and ≥1 question type selected) and "Cancel" button.

### Progress State

Dialog content transitions in-place. Shows: progress bar ("X / Y windows processed"), count of queries generated so far, and a muted note "This may take a minute." Dialog cannot be dismissed while running (clicking outside or pressing Escape does nothing). If generation fails partway, an error message replaces the progress bar showing how many queries were created before failure, with a "Close" button.

### Completion State

Progress bar fills. Success message: "Generated N queries." A "Done" button replaces the running indicator. Clicking "Done" closes the dialog. The left panel scrolls to the first newly created query and selects it.

## What Gets Retired

### Frontend — deleted

| File | Reason |
|------|--------|
| `ReviewableQueryCard.tsx` | Replaced by unified `QueryEditor` |
| `ReviewToolbar.tsx` | Review status workflow dropped |
| `GoldenSetGeneratePage.tsx` | Replaced by `AutoGenerateDialog` |
| Generate page route | No longer needed |

### Frontend — significantly changed

| File | Change |
|------|--------|
| `GoldenSetEditorPage.tsx` | Rewritten: removes `hasAutoGenerated` branch, composes left panel + right panel + `AutoGenerateDialog` |
| `QueryList.tsx` | Adds search input, source method filter chips; drops fixed row height in favour of full query text |
| `QueryEditor.tsx` | Becomes the unified editor: adds metadata footer; removes all capability gating based on source method |

### Frontend — new

| File | Purpose |
|------|---------|
| `AutoGenerateDialog.tsx` | Encapsulates configuration form, progress state, and completion state |

### Backend — minimal changes

| Change | Detail |
|--------|--------|
| `GenerateRequest` schema | Add optional `systemPrompt: str \| None` field |
| `golden_set_generation_service` | Extract hardcoded system prompt to a named module-level constant; use `systemPrompt` from request if provided |
| `review_status` field | Remains in DB schema and API responses; frontend stops consuming it. The auto-set-to-edited logic in `golden_set_service.update_query` is left in place as a harmless no-op |
