# Standalone Probe — Parser-Configuration Evidence Provider (WS1)

**Status:** Design — approved in brainstorming, pending spec review
**Date:** 2026-07-09
**Related:** [WS2 OCR parking-lot constraints](2026-07-09-ocr-ws2-constraints.md) ·
supersedes the legacy `custom_pipeline/probe.py` page classifier

---

## 1. Context

Adding OCR to the parser surfaced two independent workstreams:

- **WS1 (this spec):** make the Probe a standalone, explainable feature that produces
  rich, structured *evidence* about a document to inform how a downstream parser should be
  configured.
- **WS2 (separate spec, later):** add composable OCR tool(s) to the custom pipeline.

They are decoupled because the user is the **manual router** for now — automatic routing is
explicitly out of scope. WS1 is sequenced first: it is the evidence that makes manual (and
later automatic) parser-configuration decisions possible, it is low-risk (no heavy deps),
and it produces the ground truth used to validate WS2's OCR output later.

## 2. Core principle — mechanism, not policy

**The probe observes and reports; it does not decide.** It emits structured evidence
(per-region signals with confidence). A *separate* decision-maker/router — a human today,
an AI agent or ML router later — consumes that evidence and chooses the parser config. This
separation keeps the same evidence reusable across human, agent, and future model without
the probe ever hard-coding a routing decision.

A **suggested parse configuration** is still produced, but it is **demoted to an advisory
summary** generated by a thin, replaceable heuristic that lives *outside* the probe core and
is clearly labeled "suggested — not authoritative." It may be ignored or swapped freely.

**Observation vs. action boundary.** The probe *observes* what each region is (e.g. "this
image looks like text") — that is evidence. The probe does **not** decide the *action*
("run paddleocr on page 4") — that is policy, owned by the advisory layer / router. Region
observations use descriptive labels; the advisory layer translates them into tool actions.

## 3. Goals / non-goals

**Goals (slice 1)**
- A standalone Probe feature with its own top-level nav (`/probe`).
- Per-page **and** per-image-region evidence, each signal with a raw value + normalized
  0–1 strength; each region observation with an aggregate confidence.
- A structured, self-describing `ProbeReport` returned from a single endpoint, consumed
  identically by the UI (renders it) and an AI agent (reads the JSON).
- Configurable signals (enable/disable + tune key thresholds) via a lightweight UI popover
  and via the request body.
- Reuse of existing components: `DocumentPickerPanel` (document selection) and the
  decoupled `DocumentPdfViewer` (PDF render + bbox overlays).

**Non-goals (explicitly deferred)**
- Automatic routing / decision-making (the router is the human/agent).
- Actual OCR execution (that is WS2).
- Persistence of probe results (slice 1 is request/response, ephemeral).
- Pluggable inspection *method* beyond fitz (pdfplumber / VLM) — the seam is designed now,
  only the fitz backend is implemented.
- Pixel-texture analysis beyond numpy-Sobel edge density (OpenCV/scikit-image later).

## 4. Data contract — `ProbeReport`

The report is the product. The UI is a rendering of it; agents consume it directly. All
bboxes are normalized `[0,1]` (same convention as `DocumentPdfViewer`).

```jsonc
ProbeReport {
  document_id: string,
  filename: string | null,
  page_count: int,
  inspection: {                 // provenance of HOW it was inspected (P4 seam)
    backend: "fitz",
    backend_version: string,
    config_used: ProbeConfig
  },
  pages: PageProfile[],
  suggestion: ParserSuggestion | null,   // advisory, non-authoritative (section 2)
  duration_ms: int,
  probed_at: string             // ISO-8601 UTC
}

PageProfile {
  index: int,                   // 0-based
  page_type: "text" | "scanned" | "mixed" | "empty",   // derived page summary
  signals: Signal[],            // page-scoped signals (font_health, text coverage, copy_restricted, ...)
  regions: RegionFinding[]      // image + table regions on this page
}

RegionFinding {
  id: string,                   // stable within report; drives overlay <-> card sync
  page_index: int,
  kind: "image" | "table",
  bbox: { x0, y0, x1, y1 },     // normalized
  signals: Signal[],            // measurements for this region
  observation: {                // the probe's read on this region (evidence, not an action)
    label: "text_image" | "decorative_image" | "text_covered_image"
          | "uncertain" | "table_grid",
    confidence: float           // 0..1 aggregate (section 6)
  }
}

Signal {
  name: string,                 // "edge_density", "text_overlap", "coverage", "dpi", "font_health", ...
  value: number | string,       // raw measured value
  unit: string | null,          // "%", "dpi", null
  strength: float | null,       // normalized 0..1 contribution (null for categorical)
  detail: string | null         // short human-readable evidence
}

ParserSuggestion {              // produced by recommend.py, OUTSIDE the probe core
  authoritative: false,         // always false — it is advisory
  tools: string[],              // e.g. ["fitz", "fitz_tables"]
  ocr_pages: int[],             // page indices a router *might* OCR
  overall_confidence: float,
  rationale: string[]           // each bullet cites the signals behind it
}
```

**Observation label → overlay color** (color = the observation, maps 1:1 to the action
palette the UI presents): `text_image` → blue (OCR candidate), `decorative_image` → gray (skip),
`text_covered_image` → dashed gray (skip, text already extractable), `uncertain` → amber,
`table_grid` → green. Border style encodes confidence (solid = strong, dashed = weak).

## 5. Signals (slice 1)

Each signal is an independent, configurable analyzer (`signals/<name>.py`) that reads
primitives from the inspection backend and contributes `Signal` records. Adding/removing a
signal touches nothing else.

| Signal | Scope | Measures | New dep? | Notes |
|--------|-------|----------|----------|-------|
| `text_layer` | page | char count, `has_text_layer`, text coverage % of page | no | ported/expanded from legacy |
| `font_health` | page | ratio of PUA/CID chars → `clean`/`mixed`/`cid_corrupt` | no | ported from legacy |
| `copy_restricted` | page/doc | `doc.permissions & PDF_PERM_COPY == 0` | no | cheap; feeds advisory (camelot filtering) |
| `table_grid` | region | ruling-line count + grid regularity → table region | no | ported/expanded from legacy `table_signal` |
| `coverage` | region | image area ÷ page area | no | full-bleed vs inline |
| `dpi` | region | rendered resolution of embedded image | no | metadata only |
| `text_overlap` | region | fraction of image bbox covered by native text | no | **kills most false positives**; the `text_covered_image` signal |
| `edge_density` | region | numpy-Sobel gradient-magnitude ratio | **numpy only** | the one signal needing a raster pass; upgradeable to OpenCV behind the same interface |

`text_overlap` + `coverage` + `dpi` are pure metadata (no rendering). `edge_density` is the
only signal that rasterizes a region.

## 6. Confidence model

- **Per signal:** raw `value` + normalized `strength` in `[0,1]` via a documented, calibrated
  mapping (e.g. edge density `0.21` → strength `0.85`).
- **Per region observation:** a transparent weighted combination of the region's signal
  strengths → `confidence` in `[0,1]`, with the contributing inputs visible in the receipt.
- **Honesty caveat (state in UI + docs):** heuristic confidence is a *calibrated score, not a
  probability*. Inputs are always shown so the number is never mistaken for ground truth.

## 7. Backend

New top-level package — the probe is its own capability, **not** a CDM producer (it emits
evidence, not `Block`s / `ParsedDocument`), so it does not live under `cdm/`.

```
backend/app/probe/
  report.py         # ProbeReport / PageProfile / RegionFinding / Signal / ParserSuggestion (pydantic)
  prober.py         # orchestrator: backend.inspect() -> run enabled signal analyzers -> assemble report
  backends/
    base.py         # InspectionBackend protocol + primitive types (P4 seam)
    fitz_backend.py # the only backend in slice 1
  signals/
    base.py         # SignalAnalyzer protocol
    text_layer.py  font_health.py  copy_restricted.py
    table_grid.py  coverage.py  dpi.py  text_overlap.py  edge_density.py
  recommend.py      # thin advisory heuristic -> ParserSuggestion (outside the core)
  config.py         # ProbeConfig + defaults
```

- **Inspection backend seam (P4):** `InspectionBackend.inspect(pdf_path) -> DocumentPrimitives`
  (per page: text, image regions with bbox + raster access, drawing lines, page size,
  permissions). Signals depend on primitives, never on fitz directly, so pdfplumber / a VLM
  backend can be dropped in later without touching signals or the report contract.
- **Endpoint:** `POST /probe` with body `{ document_id, config?: ProbeConfig }` → `ProbeReport`.
  Document-referenced (reads the stored file), config-driven, agent-friendly.
- **Service:** `services/probe_service.py` fetches the stored file via the existing document
  layer, invokes the prober, returns the report; the router catches exceptions and maps to
  HTTP (per the project's router→service pattern). No repository — nothing is persisted.

### `ProbeConfig`

```jsonc
ProbeConfig {
  enabled_signals: string[],          // defaults to all slice-1 signals
  thresholds: {
    min_text_chars: 10,
    cid_ratio: 0.3,
    edge_density_min: 0.15,           // text-like cutoff (the key tuning knob)
    coverage_min: 0.10,
    table_line_min: 3
  },
  backend: "fitz"                      // fixed in slice 1
}
```

Identical whether it comes from the UI popover or an agent's API call.

## 8. Frontend

- **Nav:** new top-level **Probe** item routing to `/probe`.
- **Layout (Layout 1 — two panes, picker collapses):** pick a document via
  `DocumentPickerPanel`; on selection the picker collapses to a "Change document ▾" header
  control, leaving two panes:
  - **Left — PDF viewer:** reuse `DocumentPdfViewer`. It is already decoupled from
    `ParsedDocument` (driven by `documentId` + `Block[]`-shaped overlays + page-index nav).
    **Adapter approach (no refactor):** map each `RegionFinding` → a minimal synthetic block
    `{ id, page_index, bbox, role:'figure' }` for rendering, and drive overlay colors via the
    existing `blockColors` map keyed by observation label. *Optional follow-up cleanup:* widen
    the viewer's overlay prop to a lightweight `{id, page_index, bbox, color}` type so it is
    honestly reusable beyond CDM — not required for slice 1.
  - **Right — report:** the advisory **suggestion panel** (demoted, clearly "suggested"),
    then **page cards** (one per page: thumbnail cue, `page_type`, signal chips). Expanding a
    card shows **per-region receipts** — each signal as `value + 0–1 strength bar` and the
    observation with its numeric confidence. Card ↔ viewer selection is synced (click a card →
    scroll viewer to the page; click a region box → jump to its receipt).
- **Signals popover:** a lightweight control to toggle signals on/off and tune the key
  thresholds (edge-density cutoff, coverage %, min-text-chars), then re-probe. Builds the
  same `ProbeConfig` an agent would send.
- **Types/hook/api:** new `types/probeReport.ts`, `api/probeReport.ts`, `useProbe` hook (one
  hook per feature). The legacy `types/probe.ts`, `api/probe.ts`, `useDocumentProbe` are left
  in place until PR 2.

## 9. Legacy handling — two PRs on one branch

- **PR 1:** land `app/probe/` + `POST /probe` + the standalone `/probe` page. Legacy
  `custom_pipeline/probe.py`, `POST /documents/{id}/probe`, and `DocumentProbePanel` are left
  untouched and functional.
- **PR 2 (after PR 1 is reviewed & verified):** remove the legacy probe — `custom_pipeline/
  probe.py`, the legacy endpoint, `DocumentProbePanel`, `types/probe.ts`, `api/probe.ts`,
  `useDocumentProbe`, and the panel's mount on the documents page.

Ported heuristics (`font_health`, `table_grid`, page typing) move into the new `signals/`
analyzers in PR 1, so PR 2 is a pure deletion.

## 10. Testing

- **Signal analyzers:** unit-test each in isolation against small fixture PDFs with known
  characteristics (clean digital text, CID-corrupt text, full-bleed marketing image, scanned
  page, embedded logo, image with a text layer on top, ruled table).
- **`text_overlap`:** explicitly assert a text-covered image yields `text_covered_image`, not
  `text_image` (the key false-positive guard).
- **`edge_density`:** assert text-like vs photo-like fixtures land on opposite sides of the
  default cutoff; assert the value is stable/deterministic.
- **Prober:** assembles a well-formed `ProbeReport`; respects `enabled_signals`/`thresholds`.
- **Endpoint:** `POST /probe` returns the report for a stored document; unknown document →
  404; config overrides are applied.
- **Frontend:** report renders from a fixture `ProbeReport`; `RegionFinding`→synthetic-block
  adapter produces correct overlays/colors; signals popover round-trips a `ProbeConfig` and
  triggers a re-probe. (Backend tests run on SQLite; Postgres not required.)

## 11. Risks & open items

| Item | Note |
|------|------|
| numpy-Sobel too noisy on real samples | Threshold is user-tunable (popover); upgrade to OpenCV/scikit-image behind the same `edge_density` interface without contract change. |
| Confidence miscalibration | Slice-1 weights are heuristic; inputs shown; recalibrate against the user's small sample set. |
| Region raster cost | Only `edge_density` rasterizes; downscale before Sobel; regions are small. |
| Synthetic-block adapter feels hacky | Acceptable for slice 1; the optional prop-generalization cleanup is the honest fix. |
| Observation labels leaking into "policy" | Kept as descriptive *observations*; tool actions live only in the advisory `recommend.py`. |

## 12. Future (beyond slice 1)

- Automatic routing built on the evidence (probe becomes the feature-extractor).
- Pluggable inspection methods: pdfplumber, small-VLM backends (P4 seam already present).
- Heavier CV signals (connected components, layout/multi-column, language/script, handwriting).
- Persistence of probe reports (comparison across runs, history).
- WS2: composable OCR tools consuming manually-routed probe evidence.
